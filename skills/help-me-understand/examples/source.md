# 资料处理器：自拟教学材料

以下系统、观察和数字均为本技能作者自拟，仅供示例与测试，不是真实产品或研究结果。

1. 资料处理器接收文件后，同时进行格式检查和访问权限检查。
2. 只有两项都通过，文件才进入处理队列。任意一项失败，就返回失败原因，不进入队列。
3. 处理队列中的文件进入解释生成环节。若发现来源不完整，暂停该文件并请求补充材料；不猜测缺失内容。材料补齐后，回到解释生成环节。
4. 解释生成完成后，由用户核对内容。生成完成不表示内容已核对。
5. 一次仅包含 20 份内部报告的初测中，观察到每份报告的平均阅读时间由 8 分钟降至 6 分钟。没有说明其他影响因素是否得到控制，不能据此确定因果，也没有论文材料的测试结果。
6. 有一份文件在传输期间损坏，原因未知。

## 仅用于交互教学的假设

为了观察并行处理的变化，另设一个理想模型。它不是上面初测的数据模型，也不是实际产品的性能预测。

- 文件数量为 N，每份文件相互独立。
- 每份文件的生成耗时固定为 d 分钟。
- 同时最多生成 C 份文件；文件按批次处理，同批开始、同批结束。
- 总生成耗时为 T = ceil(N / C) × d。其中 ceil 表示向上取整。
- N = 0 时，T = 0。
- 不计检查、排队等待、传输、重试、补材料及人工核对时间。
- 示例输入：N 是 0—24 的整数，C 是 1—8 的整数，d 是 1—10 的整数。

不能用这个模型证明“并发增加会让真实阅读速度提升”，也不能把初测的阅读时间当作每份文件的生成耗时。
