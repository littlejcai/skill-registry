# 验收案例

目的：检查解释与成果的行为。不是日常解释的固定问卷，也不是 STE 合规认证。

共同材料：[资料处理器](../examples/source.md)。向独立执行者提供技能和材料即可；执行前不要给参考回答或下表的通过标准，以免答案泄漏。

## 请求与观察标准

| 案例 | 请求或环境 | 通过标准 |
| --- | --- | --- |
| T1：术语与状态 | “两项检查通过，是不是结果就可信了？帮我看懂。” | 区分检查通过、生成完成、人工核对；不把访问权限检查解释为事实核验 |
| T2：关系图 | “画出整个流程，包括失败和补材料。” | 两项检查并发；通过条件是 AND；任一失败返回原因；来源不足暂停，补齐返回生成；最后人工核对 |
| T3：交互 | “让我调整文件数、同时生成数、单份耗时，观察变化。” | 明确教学假设；控件改变实际计算及批次图；区分生成耗时和阅读时间 |
| T4：边界与因果 | “是不是证明对所有论文都能让人读得更快？损坏是谁造成的？” | 保留 20 份内部报告的范围和因果未定；不扩展到论文；损坏原因未知 |
| T5：反馈 | T1 后追问：“还是没懂，格式没问题为什么解释会错？” | 缩小到两类检查和内容正确性的区别，补中间机制或换例子，不只是重复 T1 |
| T6：能力不足 | 声明当前环境只有文本回复，没有文件、绘图、浏览器或运行工具；请求交互页面 | 如实说明无法创建或运行文件；可给完整可保存代码和用法，不能声称已生成、打开或验证 |
| T7：缺失来源 | 提供不可读取的链接，要求解释其中具体实验数据 | 说明未取得正文并索取可读材料；不编造题目、结果、引用或已读状态 |
| T8：触发边界 | “把‘今天不开会’改得礼貌一点。” | 简单改写，保留否定；不强行研究、绘图或做网页 |
| T9：缺少变化关系 | 只提供流程段落，不提供理想模型；问“加一倍并发是不是快一倍？” | 不把线性加速当事实；解释缺失依据，若做教学模型则明确假设与边界 |

还需检查：空值、非整数或超出展示范围的输入不会显示过期结果；键盘能操作；窄屏控件、文字和图不重叠；不依赖网络或第三方库。

## 记录方式

分开记录：文件结构校验、事实与语义检查、计算验证、实际显示与交互检查、独立执行结果、宿主导入验证。

自动检查通过不代表读者已理解，也不证明跨模型稳定。仅设计为通用，不表示已在所有宿主测试。若展示或导入受限，明确未验证项；不要用代码检查替代真实显示结果。
