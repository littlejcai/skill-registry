# 生图通道要求

本 Skill 不绑定任何生图服务：`image.mjs --action prompt` 只产出确定性提示词和风格板（`referenceImage`），真正成图由运行本 Skill 的 agent 用当前会话可用的生图能力完成。选通道前先过下面五条，任一条不满足就换通道，不要靠加长提示词硬凑。

## 通道必须满足

1. **支持参考图**：能把 `referenceImage` 与提示词一起传入（图生图、多图输入或 style reference 均可）。纯文生图无法保证同批卡牌风格一致，只适合单卡应急，且必须逐张人工验收。
2. **输出栅格图**：模型生成的 PNG 或 JPEG。不接受 SVG、程序化图形、占位图，也不接受用本地素材顶替。
3. **无水印无文字**：画面内不得出现平台水印、Logo、校徽、文字或角标。服务商强制加标识时，先确认能否按账号策略关闭；关不掉就换通道。
4. **提示词长度上限 ≥ 2k 字符**：本 Skill 的提示词约 1.6k 字符。上限偏小的通道（例如 1000 字符）会截断固定风格段，直接导致画风漂移。
5. **分辨率 ≥ 870×660，推荐 4:3**：例如 `1152x864`。规范化会居中裁切到 870×660，长宽比偏差过大会裁掉主体。

## 选通道时的检查顺序

参考图支持 → 是否强制水印 → 提示词长度上限 → 输出尺寸与格式 → 成本与耗时。前两项决定成品能不能用，后三项只影响效率。

## 即使通道合格，验收也不能省

每张图仍按 `image.mjs` 返回的 `acceptance` 逐条验收；不通过只允许在原提示词末尾追加具体偏差，不得改写固定风格段。多卡先生成一张风格校准图，通过后其余卡复用同一风格段、同一参考图与同一验收标准。

## 没有合格通道时

- **不要**用不满足上述要求的通道凑图；宁可不交付插画。
- 停在 `review`，向用户说明缺的是哪一项能力（参考图 / 去水印 / 长度 / 尺寸），并给出可选路径：用户自行提供图片、指定可用通道，或仅要文字版卡组。
- 注意当前渲染器要求每张 `selected` 卡都带插画，纯文字卡组需要另行改造版式，不能直接渲染。

## 与渲染阶段的关系

插画必须规范化为 `870×660 JPEG` 后写入 `card.illustration.file`；`candidate-set` 里的文件名只是登记，不构成能力证明。`render.mjs` 只接受该格式，缺失或格式不符会在渲染阶段报错。
