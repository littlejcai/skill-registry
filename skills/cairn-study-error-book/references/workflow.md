# 试卷图片识别 · 详细工作流

本文件是 SKILL.md 的配套细则。当需要处理"试卷/作业照片 → 错题整理"时按此流程执行。
核心目标：**读全、读准、只列真错题**。

---

## 0. 开工原则

- **先读全，不猜**：任何关键字段没有读到、读不清、两次读取结果冲突，都不算读完。
- **每处歧义都要闭环**：OCR 冲突 → 放大 → 再读 → 仍冲突 → 更高倍/更清晰裁剪 → 直到能给出确定值。
- **颜色只定位，内容定结论**：翻拍/扫描后红笔可能变灰变黑，绝不能因为"没检测到红色"就认为没有批改。
- **逐题独立校验**：学生写什么不轻信，每道题自己算一遍；先排除正确项，剩下的才是错题。

---

## 1. 分层读取（L1 通读保底，L2 字段级，L3 兜底）

| 层级 | 做法 | 目的 |
|---|---|---|
| L1 | Read 原图（整页通读） | 完整题干与跨栏/跨行文本的唯一权威来源，防止题目被裁剪拆散 |
| L2 | 对"待确认字段"裁剪 5~8 倍 + 对比度增强，并行读取 | 读取具体数字/汉字/符号；字段级，不做整页重读 |
| L3 | 仅当原图 OCR 整体失败时：四象限分区（相邻块 overlap ≥ 60px），并行 Read | 兜底重建整页信息，仍以 L1 布局拼装题干 |

L2 命令（批量模式，一次裁完所有歧义区；同栏候选合并为列 box + `--split` 自动分块）：
```bash
python3 <skill>/scripts/crop_zoom.py <image> --batch regions.json --outdir /tmp
```
单区域模式（坐标可带 `--coords`）：
```bash
python3 <skill>/scripts/crop_zoom.py <image> <x0,y0,x1,y1> --zoom 6 --contrast 2.0
python3 <skill>/scripts/crop_zoom.py <image> <x0,y0,x1,y1> --zoom 8 --gray --contrast 2.0
python3 <skill>/scripts/crop_zoom.py <image> 221,625,393,736 --zoom 6 --coords permille --gray --contrast 2.0
```

坐标获取：先用 L1/L2 的输出确定目标字段大致位置。`--coords permille` 可直接用 Read 返回的千分比 box（免换算）；`--split` 会把超限大图切成带 60px 重叠的小块（输出 `_p1/_p2…`），适合"整栏一图"合并读取。

**四个实测踩坑（必读）：**
1. **Read/OCR 返回的 box 是千分比坐标（0-1000），不是像素**。传给 crop_zoom 前必须换算：`x_px = x/1000 × 图宽`、`y_px = y/1000 × 图高`；直接用千分比当像素裁剪会裁到空白/黑图。也不要以 OCR box 的 y 位置为绝对准，OCR 框常有几十像素偏差，裁剪时给足上下余量。
2. **Read 对单边超过 4000 像素的图片会直接过滤**。裁剪后尺寸 = 区域宽/高 × zoom，需保证两边都 ≤ 4000；超了就把区域拆成几块分别放大，或降低 zoom。
3. **多栏试卷的 OCR 千分比框经常整体错乱（把全页内容压进一条窄带）**，不能据此定位。正确做法：以四象限分区图的 OCR 为准判断布局；首次裁剪按"分区内相对位置 + 足量边距（±50px 以上）"估位，一次不成再修正一次即可收敛，不要反复微调。
4. **插图处理（决策树 + 及时止损）**：OCR 对纯图形区域（几何图、月历、照片）失败是正常现象，不是读取失败，不要反复放大。先问"判定这题需要图的什么信息"——信息能由题干+推理补全（垂直/对折/月历等）→ 不读图；答案依赖图（看图列式、数轴定位）→ 插图区整块独立裁剪（不合并、不 `--split`、**首次给足 ±100px 边距**），zoom 3~4，以视觉描述读取。**需要精确值时优先数学排除 + 卷面更正痕迹**（真实案例：选择3 数轴 0~2000 黑点"更靠近1000"，靠选项积计算排除 C=1550 中点偏 2000、B=2236 超范围，配合"划C标D"痕迹即定案）——**读到能判定即停，定性描述足够就不要再放大，禁止像素级定位**。**被划掉的选项答案 OCR 可能读成当前值（"划C标D"被读成(C)），选项题必查插图/涂改痕迹**，这能发现 L1 漏掉的错题。**禁止现场写未经验证的像素分析脚本**（刻度线/数字易误判为黑点），需要精确读数用 Read 高倍+描述+二次确认。

## 2. 交叉验证（解决 OCR 冲突）

- 同一字段至少两次独立读取（换裁剪范围/换放大倍数/换灰度）。
- 结果冲突时：以**最高倍、最清晰**的一次为准；仍不决 → 直接查看裁剪图画面确认。
- 第 3 层读取依然失败的字段，标记为"无法确认"，写入交付说明，不得猜测。

### 高频误读清单（手写体/印刷体易混淆）

| 易混淆 | 示例（真实案例） |
|---|---|
| 5 ↔ 8 | "158" 被读成 "155"、"230" 被读成 "220" |
| 8 ↔ 9 | 个位答案 8 被读成 9 |
| 二 ↔ 四 | 星期答案 "四" 被读成 "二" |
| 146 ↔ 148 | 粽子总数 148 被读成 146 |
| 25 ↔ 10 | 农历推算日期 |
| 35 ↔ 45 | 角度答案 |
| 西 ↔ 南 | 方向题题干文字 |
| 1□ ↔ 19 | 两位数乘法的第二个因数 |

## 3. 批改痕迹分析

```bash
python3 <skill>/scripts/red_mark_detect.py <image> --out marks.png
python3 <skill>/scripts/red_mark_detect.py <image> --sample x0,y0,x1,y1
```

- 全图红笔检测 → 得到笔迹带区域 → 对每个区域高倍放大确认内容。
- 区域采样 → 判断该处笔迹颜色倾向（redish/blackish），用于推测"学生自改"还是"老师批改"。
- **内容判读规则**：
  - 数字/答案上画叉、整行划掉 → 该答案是错的（原答案）。
  - 旁边/下方另写数字 → 该数字为正确答案（更正）。
  - 空栏上方打勾 → 正确。
  - 题号旁红圈/红字 → 多为判错标记。
  - 正文被圈注 → 常是老师提示，需结合题目判断。

## 4. 逐题答案校验（校验驱动，先算对错再确认）

对每一题独立计算/推理验证（不依赖卷面答案）。校验要点见 `references/answer-checks.md`。
流程：
1. 先算出正确答案；
2. 对照卷面首读答案 → 一致的**直接排除**（不再放大确认，节省大量时间）；
3. 不一致、首读缺失或模糊的 → 进入待确认清单，L2 放大确认卷面真实答案（排除 OCR 误读造成的假错题）；
4. 确认后明确记录"我的答案"（卷面划掉/更正前的值）与"正确答案"。

确认量 ≈ 错题数（通常 2~8 个字段），而非整卷所有答案字段。

---

## 5. 交付说明要点

- 只列确认的错题；无法判断的题（照片截断、答案不可见）单独说明，**不猜**。
- 注明整理范围（如"照片可见部分：计算 23 分+填空 24 分+选择 14 分"）。
- 卷面批注（如分数"84"）如实转述，不下推断结论。
- **每题详解嵌入卷面证据图（离线优先）**：该错题 L2 确认用的裁剪放大图（涂改/更正特写、依赖图的插图区）复制到主目录 `<试卷名>_错题图片/` 子文件夹，md 用相对路径 `![](<试卷名>_错题图片/xxx.png)` 引用，与 md 一起交付（离线可查看，不依赖网络 URL）。
